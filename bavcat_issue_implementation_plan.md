# OwnerPulse Acceptance List — Comprehensive Project Analysis & Action Plan

This document contains an exhaustive, point-by-point analysis of all 50 items from the **OwnerPulse FINAL Acceptance List** (September 9, 2026), covering **Section OP (Owner Portal: OP-01 to OP-22)** and **Section DR (Director Portal: DR-01 to DR-28)** against the active Laravel backend codebase (`Owner-Pulse-backend`).

---

## Executive Summary & Classification Matrix

Out of the 50 points:
- **Frontend Only Issues (16 items)**: Routing/tab placement, UI layout/CSS, conditional form fields, modal confirmations, and missing UI views where the backend API is already functional.
- **Backend Only / Data Logic Fixes (14 items)**: Status handling (`pending` vs `open`), unified PTO data store aggregation, multi-date logging support, compliance renewal endpoint, auto-generated IDs, and dynamic settings calculations.
- **Full-Stack / Integrated Fixes (15 items)**: Missing end-to-end persistence (At-Risk retain, waitlist modal submissions, custom discount creation), where both backend API endpoints and frontend form wiring are needed.
- **Client Misunderstanding / Data Explanations (5 items)**: Areas where the backend calculates correct live numbers based on real database records (e.g. unique families vs total entries, live QB cash flow), requiring a concise client response.

## User Review Required

> [!IMPORTANT]
> **Key Architecture Decisions for Review:**
> 1. **Unified PTO Store**: We will standardize `staff_pto_logs` as the single authoritative table for all PTO entries across Daily Log, PTO Tab, and Payroll Submissions. All summary bars, employee balances, and YTD metrics will query this single source.
> 2. **No Invented Numbers / Zero States**: When capacities, targets, or revenues are not entered by the user or synced from QuickBooks, the API and UI will return clean empty states (`null` or `0`) instead of fallbacks like 500/500/1000 or arbitrary 85% rings.
> 3. **Compliance Renewal Endpoint**: A dedicated `POST /api/compliance/items/{id}/renew` endpoint will be added to update the item's expiration date to a new valid future date, resetting compliance status to compliant.
> 4. **Multi-Date Logging**: `logPto` and `logSubstitute` endpoints will support an array of individual dates (`dates: [...]`) in a single payload to match the payroll day-entry workflow.
